# Edit and review a talk

Work on a new local copy of `assets/template.html`. Replace the starter text with the audience's question, the speaker's approved words, the example, evidence, limits and invitation. Give each talk its own deck identity; retain stable slide IDs within that talk's revisions.

The template provides labeled navigation, notes, overview, text editing and HTML download. Browser editing is plain text. It does not interpret a supplied string as HTML or run source instructions. Browser storage is local to the browser and deck identity; inspect or remove a saved draft before using a shared machine.

While typing, arrow and space keys should remain editing keys. Leave the editor before using presentation navigation. Inspect long headings and source notes at narrow widths rather than shrinking a desktop composition until it is unreadable. Keyboard and touch access are software checks; they do not establish that an audience understands the talk.

A downloaded copy contains the authored slide text, speaker notes and sources. Reopen it as a separate file and verify the content and independent deck identity. Downloading is not publication approval. Do not include private sources or internal notes in a file intended for another audience.

Check print preview and the document with JavaScript unavailable; the slide sequence should remain readable. The package contains no external fonts, images, service endpoint, document converter or publishing integration. Do not promise unsupported presentation features; use the controls actually present in the tested template.
